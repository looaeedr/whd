# WHD ↔ HA / Node-RED Leaving-Home Power-Off Integration Usage

<!-- WHD_HA_POWEROFF_INTEGRATION_USAGE_V1 -->

## Boundary

This contract covers the real leaving-home / 「上班了」integration boundary:

```text
current leaving-home request
→ WHD handoff/drain evidence
→ WHD SAFE / NOT_SAFE / ERROR
→ request-bound HA projection
→ HA/Node-RED actuator decision evidence
→ external Windows graceful shutdown actuator
→ scheduler durable resume evidence
→ WHD R11 combined acceptance verification
```

WHD owns the evidence and verification layers only. **WHD does not issue the Windows shutdown command.** The final actuator belongs to Home Assistant / Node-RED under O-2.

## Machine owners

- Safety truth: `tools/workstation_poweroff_gate.py`
- HA transport projection: `tools/whd_poweroff_ha_bridge.py`
- End-to-end evidence verifier: `tools/whd_poweroff_end_to_end_acceptance.py`
- Durable resume semantics: native `WHD_EXECUTION_RECORD_V2` + `tools/execution_invocation_exit.py`

Do not copy these policies into Node-RED, prompts, or Skills.

## Current request identity

Every integration evidence object must be bound to the current:
- `poweroff_request_id`
- `evidence_revision`

A SAFE receipt from a previous request or previous revision is invalid for the current request.

## HA / Node-RED actuator decision evidence

The external HA/Node-RED side reports evidence using:

```json
{
  "schema": "WHD_HA_ACTUATOR_DECISION_V1",
  "authority": "HA_NODE_RED",
  "poweroff_request_id": "REQ-CURRENT",
  "evidence_revision": "REV-1",
  "decision": "ALLOW",
  "actuator_invoked": true
}
```

Rules:
- WHD projection `SAFE` → HA may report `ALLOW` + `actuator_invoked=true`.
- WHD projection `NOT_SAFE` or `ERROR` → HA must report `BLOCK` + `actuator_invoked=false`.
- An ALLOW for a non-SAFE projection is rejected by R11.
- The evidence record proves the HA/Node-RED decision boundary; it does not move actuator ownership into WHD.

## Scheduler resume after PC-off

For a SAFE request that actually enters the external actuator path, durable scheduler-resume evidence uses schema `WHD_SCHEDULER_RESUME_EVIDENCE_V1` and preserves:
- current `poweroff_request_id`
- `pre_shutdown_local_head`
- `remote_head`
- exact `chain.next_issue + chain.next_action` when a successor exists
- live scheduler/slot provenance when scheduler-owned
- exact structured nonblank `next_action` until terminal
- post-poweroff resume must not recreate legacy checkpoint/claim/Guard state

The next scheduler invocation resumes that exact next action automatically. It does not wait for another user "continue".

## R11 verifier result

`tools/whd_poweroff_end_to_end_acceptance.py verify ...` is evidence-only:
- current SAFE + matching external ALLOW + complete resume evidence → `ACCEPTED / END_TO_END_ACCEPTANCE`
- NOT_SAFE/ERROR + matching external BLOCK → `ACCEPTED / NEGATIVE_PATH_ACCEPTED`
- stale SAFE, identity mismatch, missing resume evidence, or actuator invocation on non-SAFE → `REJECTED`

## Prohibited implementation

WHD source must not contain or invoke a Windows shutdown actuator such as `shutdown.exe`, `Stop-Computer`, shell shutdown commands, or equivalent mutation-capable OS APIs for this integration.
